# v0.1.1

这一版集中在**「失败要能被看见」**：音频丢包、图片流串扰、握手超时、发送失败这四类问题
此前都只能靠异步事件或干脆靠猜，现在都能在返回值或事件字段里读到。

v0.1.1 is about **making failures visible**. Packet loss on the audio path, image
reassembly contamination, handshake timeouts and send failures used to surface
only as an asynchronous event — or not at all. Now they are readable in the
return value or in the event itself.

## 变更 / Changes

### 音频事件带上了序号、时间戳与丢包计数

`GlassesEvent.Audio` 新增三个字段：

| 字段 | 含义 |
|---|---|
| `seq` | 本端自增的块序号（MASS 头上没有序号，这是 SDK 补的） |
| `timestampMs` | 本端收到该块的时钟时间（`elapsedRealtime`，含休眠） |
| `droppedBefore` | 这一块之前丢掉了几个 RX 块 —— 即音频流在这里有个洞 |

三者都有默认值，构造处不必改。用 `componentN` / `copy` 解构的地方要按新参数表调整。

`GlassesSession` 同时补了三个诊断访问器：`rxDroppedChunks`、`rxDroppedBytes`、`rxStaleChunks`。

New fields on `GlassesEvent.Audio`: `seq`, `timestampMs` and `droppedBefore`
(a gap indicator). All three have defaults, so construction sites keep compiling;
destructuring sites need the new arity. Three new diagnostics on the facade:
`rxDroppedChunks`, `rxDroppedBytes`, `rxStaleChunks`.

### 图片重组不再会串流

半成品的判定条件从「下一条声明的总长不同」改成**协议结构信号** `FIRST_IMAGE`，另加
15 s 空闲超时。此前上一条被截断、下一条恰好同样长度时，字节会首尾相接并被提前判完成，
交付一张损坏的 JPEG；上一张正常完成后，同长度的下一张还会永远不交付。

Image reassembly now uses the `FIRST_IMAGE` structural boundary plus a 15 s idle
timeout, instead of guessing from the declared length.

### `SendResult.Queued` 的语义变严

`Queued` 现在准确表示「SAR 已受理」：已进车道并交给链路。信道配额已满、载荷超过远端
MPS 这类当场就能判定的失败，改为**同步返回** `Rejected`，不再伪装成 `Queued` 等一条异步错误。

`Queued` now means the SAR accepted the frame. Failures that are decidable on the
spot (lane quota full, payload over the remote MPS) return `Rejected` synchronously.

### 握手超时有了自己的错误码

新增 `208 HANDSHAKE_TRANSIENT`：握手超时、对端未确认这类**瞬时**失败走它；
`108` 保留给「token 永久无效」。两者仍是终态（SDK 不会把「设备不可用」伪装成
「正在连接」），但宿主现在能区分该不该重试。

New code `208 HANDSHAKE_TRANSIENT` for timeouts and unconfirmed handshakes;
`108` stays for a permanently invalid token.

### 时钟改用 `elapsedRealtime`

`UptimeClock` 从 `System.nanoTime()` 换成 `SystemClock.elapsedRealtime()`
（CLOCK_BOOTTIME）。前者在深度睡眠期间不前进，SAR 重传与退避计时会「欠账」。

`UptimeClock` switched from `nanoTime` to `elapsedRealtime` (BOOTTIME), which keeps
advancing in deep sleep.
